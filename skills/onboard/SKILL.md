# 사수 온보딩

먼저 `${CLAUDE_PLUGIN_ROOT}/agents/senior-dev.md`를 읽고 그 원칙·말투·장부 규칙을 따른다.
ECC `codebase-onboarding`을 주니어용으로 고친 절차다. 결과물은 2분 안에 읽혀야 한다.

## 1. 정찰 (전부 읽지 않는다)

한 번에 같이 확인한다:
- 패키지 파일: package.json, pyproject.toml, go.mod, Cargo.toml, pom.xml, build.gradle, Gemfile
- 프레임워크 설정: next.config.*, vite.config.*, settings.py, main.py, app.*
- 진입점: main.*, index.*, server.*, cmd/, src/main/
- 폴더 구조 상위 2단계 (node_modules, dist, build, .git, __pycache__ 제외)
- 도구: 린터·포매터 설정, Makefile, Dockerfile, CI(.github/workflows), .env.example
- 테스트: 테스트 폴더와 파일 이름 규칙
- 팀 지식: `.sasu/knowledge.md`가 있으면 읽는다

## 2. 이해

- 요청 하나를 처음부터 끝까지 따라간다: 어디로 들어와서, 어디서 검증하고, 로직은 어디 있고, 어떻게 저장되는지.
- 관례를 찾는다: 파일·함수 이름, 에러 처리 방식, 테스트 쓰는 법, 커밋 메시지 형식(`git log --oneline -20`).
- 이 프로젝트만의 용어(도메인 단어, 줄임말)를 모은다.
- 실행·테스트 명령은 **실제로 돌려 보고** 확인됨/미확인을 표시한다. 오래 걸리거나 외부 연결이 필요하면 돌리지 않고 미확인으로 둔다.

## 3. 안내서 쓰기

`.sasu/onboarding.md`에 쓰고, 대화에는 요약만 보여 준다. 이미 있으면 읽고 바뀐 부분만 고친다.

```markdown
# <프로젝트> 안내서
> 사수가 <날짜>에 작성. 틀린 곳이 있으면 고쳐 주세요.

## 한 줄 요약
## 기술 스택 (표: 영역 · 기술 · 버전)
## 폴더 지도 (뻔한 폴더는 생략)
## 요청 하나 따라가기 (단계별 `파일:줄`)
## 자주 쓰는 명령 (확인됨/미확인 표시)
## 우리 팀 관례
## 용어집
## 이럴 땐 여기를 보세요 (표: 하고 싶은 일 → 볼 곳)
## 첫 주 과제
## 아직 모르는 것
```

### 첫 주 과제

작고, 실제로 이 저장소에 있는 일로 3개를 고른다. 각각 볼 파일과 끝났다고 볼 기준을 적는다.
1. **읽기**: 핵심 흐름 하나를 따라가서 요약해 보기
2. **테스트 하나 추가**: 테스트가 얇은 곳 (`파일` 지목)
3. **작은 수정**: TODO, 오타, 작은 리팩터링 중 하나 (`파일:줄` 지목)

### 아직 모르는 것

확신하지 못한 것(배포 방법, 환경 변수 값, 결정 이유)은 지어내지 말고 질문 장부에 남긴다.
먼저 `open`으로 이미 열린 질문인지 보고, 있으면 그 번호만 안내서에 적는다. 다시 온보딩해도 같은 질문이 쌓이지 않게.
```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/sasu.py" ask-log "운영 배포는 누가, 어떻게 하나요?" --who "<이름>"
```

## 하지 않는 것

- 의존성을 전부 나열하지 않는다. 코드 쓰는 방식에 영향을 주는 것만 적는다.
- README를 베끼지 않는다.
- CLAUDE.md를 마음대로 만들거나 고치지 않는다. 필요하면 제안만 한다.
